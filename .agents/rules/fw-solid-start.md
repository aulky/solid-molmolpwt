# SolidStart — quick card
Applies only if package.json dependency @solidjs/start. Otherwise ignore this rule.
Deep guide: `.agents/guides/frameworks/solid-start.md` — read before non-trivial routing/data/server work. Reactivity
basics live in `.agents/rules/fw-solidjs.md`, not repeated here.

## Project shape
- v2 is a Vite plugin, not a standalone framework: `solidStart()` + `nitro()` in `vite.config.ts`. No `app.config.ts`,
  no `vinxi` — v2 replaced Vinxi with Vite's own Environment API.
- File routes live under `src/routes/**` (`routeDir`); default export is the page, exported `route` configures its
  `RouteDefinition`, exported `GET`/`POST`/`PUT`/`DELETE`/`PATCH` make it an API route.
- `src/entry-server.tsx` (`createHandler`+`StartServer`) / `src/entry-client.tsx` (`mount`+`StartClient`) are the two
  hydration boundaries — nothing they import transitively may touch `window`/`document` at module scope.

## Invariants (MUST / NEVER — with reason → alternative)
1. NEVER put config in `app.config.ts` or import `vinxi/*` — v2 has neither. Config is `solidStart()`+`nitro()` in
   `vite.config.ts`; `vinxi/http` is now `@solidjs/start/http`.
2. MUST name a route param folder/file `[id]` (required), `[[id]]` (optional), `[...rest]` (catch-all) only, and
   NEVER assume a parenthesized `(group)` folder is stripped from the URL — verified in the
   `@solidjs/start@2.0.0` file-router (2026-09): it rewrites only those three bracket shapes; `(group)` ships as a literal
   segment. Confirm your build's actual routes first; group with a real segment and a shared layout component instead.
3. MUST put `"use server"` as the first line of a server-only function body and call it like a normal async
   function from the client — never hand-roll a `fetch` to it or guard it with `isServer`.
4. NEVER read the request, cookies, or session with raw Node/`vinxi` APIs — use `getCookie`/`setCookie`/
   `useSession`/`getSession` from `@solidjs/start/http`, or `getRequestEvent()` from `solid-js/web` for the raw
   `request`. These work in dev and every Nitro deployment target alike.
5. MUST trigger a mutating `action()` through `<form action={theAction}>` or `useAction()`, not by calling the
   exported function directly — direct calls skip single-flight revalidation, so a `query()` read elsewhere goes stale.
6. NEVER let two `query()`/`action()` calls share a name string — the 2nd argument is a hard-coded cache key, not
   the JS identifier; two loaders reusing one string silently share (and clobber) one entry.
7. MUST return `redirect(url)` / `reload()` / `json(data)` from `@solidjs/router` (not a hand-built `Response`) from
   a query/action that redirects or refetches — the single-flight mutation flow special-cases these helpers.

## Patterns
- Data read: `const post = createAsync(() => getPost(params.id))`, `getPost = query(fetchPost, "post")` — dedupes
  across client/server, integrates with `<Suspense>`.
- Data write: `const save = action(async (id, data: FormData) => { "use server"; ...; return redirect("/posts"); })`;
  read pending/error state with `useSubmission(save)`.
- API route: `src/routes/api/health.ts` exporting `export function GET() { return json({ ok: true }); }`.
- Middleware: `solidStart({ middleware: "src/middleware.ts" })` exporting `createMiddleware([...h3Fns])` from
  `@solidjs/start/middleware`. Head tags: one `<MetaProvider>` near the root, `<Title>`/`<Meta>` per route from
  `@solidjs/meta` (installed transitively via `@solidjs/start`).

## Pitfalls
- Calling a server-only function during render (outside an event handler/action) round-trips over the network
  every render — hoist into `query()` + `createAsync` so it's cached and SSR-streamed.
- Default `serialization.mode` is `"json"` (CSP-friendly `JSON.parse`) — opt into `serialization: { mode: "js" }`
  (Seroval) for smaller payloads if your CSP allows `eval()`.
- `createAsync`/`createResource` with no `<Suspense>` above it: renders nothing, no fallback shown.
- Editing `.output/` by hand — Nitro's build output (like `dist/`), regenerated by the project's build command (root `AGENTS.md`).

## Example — bad → good
```ts
// bad: no cache/dedup, ad-hoc redirect
export async function GET() {
  const user = await db.user.find();
  if (!user) return new Response(null, { status: 302, headers: { Location: "/login" } });
  return new Response(JSON.stringify(user));
}
```
```ts
// good: a query the rest of the app can share, cache, and revalidate together
import { query, redirect } from "@solidjs/router";
export const getUser = query(async () => {
  "use server";
  const user = await db.user.find();
  if (!user) throw redirect("/login");
  return user;
}, "user");
```
